# 🤝 Contributing to The Nexcape Project

First off, thank you for taking the time to contribute! 🎉

**The Nexcape Project** is driven by its community. By contributing, you are helping us build a privacy-first, secure, and transparent digital ecosystem. We welcome contributions from everyone, whether you are writing code, designing interfaces, fixing typos, or triaging issues.

As an AGPLv3-licensed project, all contributions made to this repository will be released under the same license to ensure the ecosystem remains free and open for everyone, forever.

---

## 📜 Code of Conduct

We are committed to fostering a welcoming, safe, and inclusive community. By participating in this project, you agree to abide by our core values: mutual respect, constructive feedback, and a focus on user privacy and collaboration. Harassment or unacceptable behavior will not be tolerated.

---

## 🚀 How Can I Contribute?

### 🐛 Reporting Bugs

If you find a security vulnerability or a bug, please help us by opening an **Issue**:

1. Check the existing Issues to make sure it hasn't been reported yet.
2. Use a clear and descriptive title.
3. Describe the exact steps to reproduce the problem.
4. Include details about your environment (OS, hardware specs, engine version if applicable).
5. *Note: If you find a critical security flaw that could compromise user privacy, please report it privately via [insert private security email/method] instead of opening a public issue.*

### 💡 Suggesting Enhancements

Have an idea to improve user privacy, security, or performance? We want to hear it!

- Open an **Issue** using the "Feature Request" template.
- Explain the problem you are trying to solve and why this feature is essential to Nexcape's core principles.
- Provide mockups or conceptual workflows if you are suggesting UI/UX changes.

### 💻 Code Contributions

Ready to write some code? Here is the standard workflow to get your changes merged:

1. **Fork the Repository:** Create your own copy of the repository on GitHub.
2. **Clone & Branch:** Clone your fork locally and create a new branch with a descriptive name:

```bash
git checkout -b feature/your-feature-name
# or
git checkout -b fix/bug-description
```

3. **Commit Safely:** Write clean, documented code. Make sure your commit messages are descriptive and follow standard conventions (e.g., `feat: add native tracker blocking mechanism`).
4. **Push & Pull Request:** Push your branch to your GitHub fork and open a Pull Request (PR) against our `main` or `development` branch.

---

## 🛠️ Development Guidelines

To maintain the high standards required for a security-focused project, please ensure your contributions align with the following rules:

- **Zero Telemetry:** Never introduce tracking, analytics, background data collection, or hidden telemetry. Any PR doing so will be instantly rejected.
- **Security Standards:** Avoid common vulnerabilities (memory leaks, injection vectors, unsafe dependencies). Code running in the Nebula Engine or Nexcape OS must prioritize memory safety.
- **Code Formatting:** Follow the project's style guides (linters and formatting configurations are located in the root directory).
- **Test Your Code:** Ensure your changes do not break existing functionality. Include unit or integration tests whenever possible.

## 🎨 Non-Code Contributions

You don't need to know how to code to be a core part of Nexcape! We highly value:

- **Design:** Wireframes, UI elements, branding assets, and icon designs for Nexcape Browser and OS.
- **Documentation:** Improving this guide, writing technical wikis, or creating user-friendly manuals.
- **Translations:** Localizing the browser UI and documentation into multiple languages to expand user freedom worldwide.
- **Testing:** Downloading early alpha builds, hunting for edge-case bugs, and reporting performance metrics.
